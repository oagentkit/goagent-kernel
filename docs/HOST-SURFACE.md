# 宿主接入面（HOST-SURFACE）

> **这是什么**：评审（2026-11-27 §3.4 方向二「统一运行契约」）要求的**宿主最小接入面清单**——
> 让 Runtime 不需要理解几十个包的内部机制：Kernel 对外只暴露少量稳定的高层契约。
> 本文档回答三个问题：**六步主链里宿主提供什么、kernel 兑现什么**；**每个包对宿主意味着什么
> （必须接 / 可选 / 内部件）**；**文档教的 import 有没有教到内部件**。
>
> **判据**：`make hostsurfacecheck`（执行体 `cmd/hostsurfacecheck`，判据本体
> `internal/hostsurface`，已接进 `make unit` 与 `make check` ⇒ CI 会跑）。分类漏一个
> api-lifecycle 包 ⇒ 红；文档代码块 import 内部件/未登记包 ⇒ 红。
>
> **与相邻登记面的分工**：`docs/INVARIANTS.md` 管**执行正确性**（不变量谁在守）；
> 本文档管**接入叙事**（宿主该接什么）。两份各管一事，不互判。
>
> **两个「六」不是一回事**：本文的六步是**运行步骤轴**（任务从创建到介入的生命周期）；
> USAGE §3 开篇 SVG 的「六段机制」是**接入分段轴**（按能力依赖顺序教学）。前者回答
> 「链的每一步谁提供什么」，后者回答「按什么顺序学」。

## 一、主链六步对照（宿主提供 / kernel 兑现）

链条：创建 → 领取 → 执行 → 提交（副作用与状态）→ 恢复 → 介入。
每步两格都非空才叫对照——只写 kernel 那半边，宿主不知道自己要接什么。

| 步骤 | 宿主提供 | kernel 兑现 |
|---|---|---|
| create 创建 | 任务拓扑与幂等键（领域状态走 `contract` 开放键）；板与权威存储的实现 | `controlplane` 落账与重复判定（重复 run / 重复任务显式拒，先整单校验再写）、`statemachine` 合法迁移判定 |
| claim 领取 | `taskboard.Board` 存储实现（令牌由存储铸造）；worker 装配（续期时钟注入） | 租约 + 令牌 + 代次三件套：并发认领恰好一个赢家、过期可接管、代次严格递增 |
| execute 执行 | 工具实现与判定环 Stage 切片；`ptc` bindings；`backend` 后端注册 | 受管执行（租约内推进、丢失即取消）、工具披露与门禁（`tooldisclose` / `guardset`）、出进程执行档位 |
| commit 提交 | `sideeffect.Store`（幂等键）、`checkpoint` 的 `StoreCAS`、终态词表注入 | 至多一次施加（幂等键 + 租约 + 栅栏一份状态三个投影）、快照序号单调 CAS、`commitgate` 终态独占放闸 |
| recover 恢复 | 重启入口（宿主进程起来后调恢复链）；恢复所需存储实现 | `checkpoint.BuildPlan` 纯函数续跑判定（续跑而非重放）、租约过期后旧持有者提交被拒 + 新持有者接管、`reconcile` 启动孤儿回收与 Outbox 补做（事件不丢帧） |
| intervene 介入 | 审批回调与权威任务表实现（与执行面同一份权威） | `controlplane` 裁决与留痕（并发介入只有一次有效状态转换）、强制释放与 Worker 完成同账、`ownership` 跨区域 Epoch 围栏 |

底栏不变量（与 USAGE §3 SVG 底栏同口径）：**内核只判定，不处置——判定依据由宿主给，
处置动作由宿主执行**。本表不改变这条边界，只把「链的每一步」摊开。

## 二、包三分类（全量，覆盖 api-lifecycle 登记面）

**三档判定依据**：

- **必须接**：装配上述六步主链的默认机制面——不接它，链上那一步没有默认实现
  （含 USAGE「怎么读」标为**必接**的三组能力：契约面 / 工具判定环 / 报告协议）；
- **可选**：按需装配的增强、判据、门禁与契约测试套件——宿主不接不破坏链的完整性；
- **内部件**：本仓门禁执行体与 `internal/*` 判据包——Go 可见性或本仓 CI 已挡住，
  **宿主不该直接 import**，文档教到即红。

**地面真相（如实登记，2026-11-28 勘察）**：USAGE 教 23 个包的 import，goagent-runtime
参考实现真用 15 个，交集 12；`backend` / `controlplane` / `invocation` / `tenant` /
`worker` / `coord` 是**宿主真在用但 USAGE 没有接入节**的六个包（本文先给分类定性，
USAGE 补节是教学面欠账，不阻塞本清单）；反向「教了但参考实现没用」的 14 个是判定环 /
门禁面——参考 runtime 是存储编排层，不跑模型侧工具环，属正常差异而非文档说谎。

## 三、判据边界（如实登记）

- 机器判得了「**分类覆盖全集**」「**文档没教内部件**」「**六步两格非空**」，判不了
  「六步对照写得对不对」——内容质量归 review；也判不了「某包该不该从可选升必须接」
  ——那是接入策略的演进判断，改分类是人维护登记面的动作（改完门禁照样核覆盖与白名单）。
- 文档 import 白名单只看 README 与 USAGE 的**代码块 import 声明**（单行与分组两形态）；
  正文提到的包名、`go get` 命令行、CHANGELOG 历史快照都不算「教宿主 import」。
- 「USAGE 没教但宿主真在用」的六个包（见 §二地面真相）是**教学面欠账**：本清单先给
  定性，USAGE 补节另计——清单的存在恰恰让这类欠账有了对账的基准。
