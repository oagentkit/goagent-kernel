# 三平面划分（PLANES）

> **这是什么**：评审（2026-11-27 §3.3 问题四）要求控制面/执行面/恢复面**概念上
> 必须分清**——不一定要拆成三个项目，但新包该进哪面、跨面依赖哪个方向合法，
> 要有判据可依，不靠 review 感觉。
>
> **判据**：`make planecheck`（执行体 `cmd/planecheck`，接进 `make unit` 与
> `make check`）：包→平面映射覆盖全集、跨面方向逐对登记（未登记方向对门禁隐形
> ——与 dependency_direction「未登记包」同向）、禁止方向被真实 import 命中 ⇒ 红。
>
> **与相邻登记面的分工**：`docs/HOST-SURFACE.md` 管**宿主视角**（该接什么）；
> 本文档管**内核视角**（机制住在哪面、面间怎么连）。横切包（contract/protocol 等
> 谁都要用的）标 `X`，不参与跨面规则。

updated: 2026-11-28

## 一、三平面定义（动词清单）

| 平面 | 动词（评审原文） | 一句话判据 |
|---|---|---|
| **C 控制面** | 任务创建、暂停、取消、审批、介入、调度决策 | 「决定要不要做、谁来做、还做不做」 |
| **E 执行面** | Worker 执行、工具调用、状态更新、Checkpoint | 「正在做」——推进任务的活 |
| **R 恢复面** | 租约、接管、重放、恢复、终态收敛 | 「断了之后怎么回到正轨」 |
| **X 横切** | 契约、词表、指标等谁都要用的判据面 | 不参与跨面规则（谁 import 它都不算跨面） |

**判定口径**：一个包只有一个**主平面**（映射表「平面」列的首字）；确需两面栖身的
包标复合值（如 `C+R`），主平面取首字参与跨面规则。复合是例外登记，不是常态——
能拆则拆。

**跨面规则表**（观测方向必须登记——未登记方向对门禁隐形，与 dependency_direction
「未登记包」同向；禁止方向可预防性登记，被真实 import 命中即红）：

| from | to | 裁决 | 理由 |
|---|---|---|---|
| C | E | 允许 | 控制面裁决写执行面效果行是「权威唯一」的设计本体（#268/#278：AdjudicateWritesThroughEffectAuthority 走副作用闸同一份状态）；审批裁决读执行面能力声明（gatecheck/preset→egress）是「读状态」不是「改状态」——与任务板同账经由 X 面完成，不经旁路 |
| R | E | 允许 | 恢复面补发事件/重放写执行面状态——恢复的定义就是把执行面推回正轨（Outbox 补做、水位线推进、孤儿回收） |
| R | C | 允许 | 收尾路由要读控制面的介入信号（deadline.Route 认 steer.ErrSteered 哨兵）——终态收敛必须认识「被改道」 |
| E | C | 禁止 | 执行是被驱动的：执行面依赖控制面裁决入口会让执行链反向长出调度逻辑。需要「决定」时把判据下沉为 X 或由宿主注入（预防性禁令，反向验证靶） |
| C | R | 禁止 | 介入走权威状态传达（C→E 同账），不直接操纵恢复链——控制面直接调恢复机制会造出第二条收尾路径（预防性禁令） |

**观测基线（2026-11-28，回归锚点）**：生产代码非 X 跨面边 **5 条 / 3 方向**——
C→E（controlplane→sideeffect、gatecheck→egress、preset→egress）、R→E
（coord→sideeffect）、R→C（deadline→steer）；全部落「允许」规则。
**负事实**：E→C = 0、C→R = 0、E→R = 0——评审最警惕的坏方向当前干净，
这两条按预防性禁令登记（被真实 import 命中即红），也是回归锚点：
新边出现且方向变坏 ⇒ 当场显形。

## 三、判据边界（如实登记）

- 机器判得了「映射覆盖全集」「跨面方向逐对登记」「禁止方向没被真实 import 命中」，
  判不了「某个包归哪面对不对」——归类是设计判断，归 review；也判不了「允许方向
  是否被滥用」（A→B 允许不代表 A 可以把 B 当实现细节使）。
- 跨面规则按**主平面**判定（复合值取首字）——复合包的另一半面不受规则保护，
  这是如实登记的简化，不是疏漏。
- 测试代码的 import 不进判定面（与 dependency_direction 同口径：测试依赖是
  临时的，交付物里的形状才作数）。
