## 0. 读法与纪律

**核验口径**：一条结论成立与否，看的是「源码里有没有那条路径」，
不是「文档里有没有那句承诺」。本文沿用评审里最有价值的两条区分：

- **契约**（声明应该怎样）与**执行**（实际怎样）分开判——
  「注释写了不许」不等于「代码拦得住」；
- **机制面**（与「谁在用它」无关）归本仓，**装配面**（谁接哪个后端）归宿主。

**引用口径**：本文代码引用写到 `文件:行`，对应基线 `fdc4922`。
本文**不抄会过期的数字**（覆盖率、规则条数、包数一律以门禁输出为准）——
抄进来就是给自己造一份会静默过期的真相。

## 1. 一句话结论

内核的**机制密度已经够了**：认领唯一性、令牌铸造、幂等闸、单调进度、
代次、Handoff、故障注入矩阵都在。缺的不是模块，是**闭环**——
身份的作用域、租约的续期、事件的可靠交付、资源的回收、权威的唯一。

下一阶段的主题因此不是「再加机制包」，而是把**声明的保证变成可证明的保证**。

## 3. 三条硬事实（比缺陷清单更值得记住）

**（a）契约不是兑现。** TailStore 的「无空洞推进」写得很硬，但仓内没有任何
生产实现满足它——连 pgstore 都没有事件表。评审问的是「PostgreSQL 会不会自动
满足契约」，真问题是「**那个实现还没人写**」。差别决定工作量：前者改 SQL，
后者写一个面。

**（b）参考实现缺面，比实现有 bug 更危险。** pgstore 现在有 5 张表
（effect_action / effect_resource / downstream / board_task / snapshot），
**没有事件表、没有租户列、没有 `controlplane.Store`**。宿主照抄 schema 会
以为「PG 面齐了」，然后在自己的实现里把三处空白各填一次——各填一次就各漂一次。

**（c）门禁骨架已在，扩展成本低。** `worker/faultmatrix` 已经是
「故障类 × 部署模式」的可执行矩阵（6 类 × 3 模式），自检规则是
「每类至少一条用例，漏一类即红」。评审要的 8 个新场景**扩行扩列即可**，
不需要另起炉灶。

## 4. 演进路线

### L1 · 身份与租约闭环（P0/P1，机制面主要在本仓）

目标：任何一次执行都有**唯一身份**；任何一段长执行都**不会在租约过期后仍能提交状态**。

| 机制面改动 | 归谁 | 可机判验收 |
|---|---|---|
| 动作身份规范 + `ActionKeyBuilder`（Tenant + Run + Task + Action；**Attempt 不入键**） | 本仓（sideeffect / worker） | 两租户同 TaskID、同动作参数 ⇒ 无重放、无冲突；同租户不同 Run 同 TaskID ⇒ 同上 |
| 受管租约会话（`LeaseSession`：Context / Token / Fence / AssertOwned） | 本仓（worker + taskboard） | 执行超过 TTL 后，旧持有者的 Checkpoint / Complete 被**存储端条件提交**拒绝 |
| 续期调度改为按绝对到期时间 + 并发上限 + 批量续期 | 本仓（worker + taskboard 门面） | 200 在途、续期 100ms/条、TTL 15s ⇒ 无一任务在续期前失格 |
| 游标初始化契约修正（found=false ⇒ 显式起点 ⇒ MaxID） | 本仓（eventbus） | 组合用例 `CursorStore(empty) + StartCursor(100)` ⇒ 从 100 起读 |

出口条件：上表四条验收全绿 ⇒ 「一个动作至多施加一次、一次执行至多提交一次进度」
在多副本形态下**可证**，而不是「按约定应该」。

### L2 · 可靠交付与资源回收

目标：事件不丢、配额不漏、控制面与执行面同账、租户隔离落到存储。

- **可靠事件面**：Outbox / 水位线语义的**生产级 TailStore 参考实现**（仓内目前没有）
  ＋ 事件写入与业务状态同事务；
- **配额回收**：`QuotaLease` 带 TTL / Owner / 关联 Task；回收走 Reconciler，
  且**必须先确认任务租约已失效**——不能凭「心跳消失」就归还额度，否则旧任务
  可能还在真跑；
- **权威统一**：控制面强制释放 / 裁决走**同一份任务记录**（复用 taskboard 的原子
  状态迁移，或要求同一事务后端同一张表），不构造第二份可写任务状态；
- **租户隔离落到持久化面**：effect / 事件表加租户维度（现在 coord 侧支持租户作用域键，
  sideeffect 侧零租户概念）。

出口条件：事件乱序提交不丢帧；配额悬挂可安全回收；控制面并发介入只有一次有效状态转换。

### L3 · 跨域所有权

目标：跨区域多集群下不出现双主执行。

- 按区域定义**唯一 Ownership Authority**，跨区域转移用 Epoch + 确认协议；
- 网络分区期间旧域写入被 fence **拒绝**（不是「尽量」拒绝）；
- 顺序上：**先**做「多集群共享一个权威任务域」（L1+L2 齐备后），
  **再**做「多自治域之间的 Handoff」——不一开始就背跨地域双主的一致性负担。

## 5. 验证策略：扩列，不另起炉灶

评审第 6 节列的 8 个场景，映射到 `worker/faultmatrix` 的矩阵（扩行 + 扩列）：

| 评审场景 | 矩阵落位 | 适用模式 |
|---|---|---|
| K8s API 响应丢失（Job 已建、Worker 超时） | 执行幂等 | Cluster（需真集群） |
| 跨租户任务碰撞 | 身份作用域 | Standalone + Cluster |
| 长任务租约失效 | 租约闭环 | Cluster |
| 数据库主备切换 | 存储故障 | Standalone（需真 PG） |
| 事件乱序提交 | 可靠交付 | Standalone + Cluster |
| 配额悬挂 | 资源回收 | Cluster |
| 控制面并发介入 | 权威唯一 | Cluster |
| 真实 NetworkPolicy 验证 | 执行隔离 | Cluster（需真集群） |

纪律两条：

1. 需要真集群的格**必须填 `matrixCase.requiresEnv`**（显式 `Skipf` + 打印所需环境），
   不许「观察到但跳过」——跳过必须写清「哪个事实在该环境不存在」；
2. 矩阵自检（每类至少一条用例）继续是门禁红线：**矩阵只准扩，不准删**。

## 6. 场景化部署配方与当前缺口

| 目标场景 | 推荐存储 | Worker 模式 | 必需能力 | 当前缺口 |
|---|---|---|---|---|
| 单进程 Agent | Memory | 单进程有界并发 | 幂等键作用域、Context 取消 | 幂等键作用域（#261） |
| 单机持久化 | `examples/sqlitestore`（**不是 SQLite 驱动**） | 单节点 | 全状态持久化、启动恢复、进度与副作用对账 | 参考实现只覆盖 TaskBoard（#264） |
| 同机多进程 | PostgreSQL | 多进程竞争认领 | 统一租约、数据库时钟、跨进程 Token | PG 面缺租户列与事件表（#261/#264） |

## 7. 本轮明确不做（防范围蔓延）

- **不**引入 client-go：K8s 面继续零依赖手写 HTTP（依赖面纪律见 ADR-0003）；
- **不**引入 SQLite 驱动：examples 不给主 module 增传递依赖树
  （理由见 `examples/sqlitestore/doc.go`）；
- **不**在本仓实现「宿主部署拓扑」判据：拓扑归宿主，机制归本仓；
- **不**做跨地域双主：L3 的前置是 L1 + L2；
- **不**把 examples 参考实现的完备性当成本仓门禁对象：参考实现是**给宿主抄的契约**，
  不是判定面（真 PG 契约由 `make integration` 承担）。

## 8. 落地纪律（每条演进都要满足）

1. **判据先于实现**：机制面改动必须带「坏实现会红」的用例——只测「好实现能过」的
   用例，一个把数字比较写成字符串比较的错实现照样全过；
2. **门禁接线**：新判据接进 `make check`，不只挂在 CI 工作流上；
3. **文档数字有主**：可机判的数字交给门禁输出，本文不抄；
4. **反向验证**：契约类改动（TailStore、幂等键、租约）必须带**违约实现**的对照用例。

## 10. 第二轮深挖台账（2026-11-17 夜）

第一轮（#261–#279）走的是**外部评审的核验**；第二轮改成**自己下场审计**：
按「尚未被审过」的面分组并行审计（trajectory / preset、tooldisclose / skilldisclose、
budget / cost、pii、offload、protocol 净化面），每条结论**逐条对照源码坐实**，
能被复现的一律实测（仓外临时模块 / `go test -overlay`），坐实不了的写「待坐实」。

**审计面的选择依据**：本仓 #177–#258 已经把 worker / protocol 协议面 / netguard / gatecheck /
ticket / eval / sideeffect / checkpoint / coord / controlplane / eventbus / handoff / drain /
steer / commitgate / memorypipe / delta / spill / ptc / tenant / hookengine / worktree / sidetest
过了一遍；**未被系统审过**的恰好是下面这些面——它们也正是「宿主直接装配、判据全在本仓」的位置。

### 这一轮反复出现的两个形态（比单条缺陷更值得记住）

**（a）「宿主以为已保护，实际没有信号」。** 三个包各有形态，根子相同：
`pii` 的未知载荷形状静默透传（`blocked=false`）、`pii` 的 map 键不脱敏、
`offload` 的解析面不校验 path、`skilldisclose` 的空结果把宿主推向全量披露。
共同特征是「**返回了一个看起来正常的值**」——宿主没有手段区分「查过了没有」与「根本没看」。
凡是有「查一下」语义的面，**必须给三态**（命中 / 未命中 / 未能判定），二态一定漏。

**（b）声明的覆盖面与实现的覆盖面不是一回事。** `preset` 说「不可变」但只到字段级、
说「目录占用有上界」但无界点在参数描述、`pii` 说「与键名无关」但恰恰漏在键上、
`offload` 说「至少 2 位十六进制」但只查长度、`skilldisclose` 说「两种资源声明形态」但实现有第三种。
本仓纪律要求「如实声明」，而这轮说明**声明写得再细也不等于覆盖到位**——
「声明的覆盖面」本身也要被判。

### 下一轮建议（按面，不按单）

1. **三态化**：把「查一下」类接口（`pii` 的载荷形状、`offload` 的解析面、披露面的检索截断）
   统一改成「命中 / 未命中 / 未能判定」——三处同源，改一次；
2. **声明面可机判**：凡是「声明了上界 / 覆盖了形态 / 不可变」的包，都配一条**反向验证**用例，
   让「覆盖面不足」在 CI 里变红，而不是靠人读注释；
3. **宿主回调一律在锁外**：`trajectory` 的 `Summarize` 自死锁是通用形态——
   任何「宿主注入的回调」都不该在本仓内部锁内执行；
4. **值类型承诺要落到深拷贝**：切片字段会让「值类型」只挡住字段替换、不挡元素改写；
5. **可导出的词表**：内核里凡是「三处手抄」的清单（骨架标记、归一化口径、状态词表），
   都要有一条**可导出的单源** + 一条两侧比对的判据。
